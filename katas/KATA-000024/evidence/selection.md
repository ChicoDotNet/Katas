# KATA-000024 — selection before inspecting workflows

Domain: six incremental social-network capabilities (posting, timeline reading, following/feed, @mentions, http(s) links, private direct messages). Invariants: only explicit recipient sees DMs, feeds include only followed authors, follows are idempotent and directional, timelines reverse chronological, equal text is not a duplicate event, references retain event IDs. Entire malformed request rejected before processing; links are metadata, never fetched.

Language comparison: TypeScript 5.8 (tagged event/query unions, typed projections, incremental indexing; strong fit); Ruby 3.3 (excellent BDD DSL and dynamic domain model, but fewer compile-time union checks); Haskell (pure folds/ADT are elegant, compiler unavailable here); Prolog (relations excellent for feed but no local SWI-Prolog and less natural event ingestion). Select TypeScript for event union exhaustiveness and incremental projections, not because CI exists. RED/GREEN: native Node test runner + tsc. Oracle: Go 1.23, read-only scan of full event log per query and a byte-oriented parser for mention/link tokens; deliberately no TypeScript indices. Alternative: clone the same incremental indexes in Go, rejected because errors in index update ordering could be shared. Risk: both still share input contract and event sequence numbering. Compare invalid inputs, duplicate follow, private DM, no cross-visibility, ordering, mentions/URLs, and metamorphic insertion of unrelated events.

Source rights: Kata-Log's own description https://kata-log.rocks/social-network-kata is declared public domain; no linked starters or fixtures copied. Original code MIT. Contract choices (event JSON, usernames, ordering, DM visibility, link tokenization) are original and not claimed to be a faithful reproduction of third-party starters.
